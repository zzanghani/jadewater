# 제이드앤워터 매장 운영 앱 — 현황 정리 (2026-11-01 기준)

> 목적: 나중에 이 앱을 구글 플레이·앱스토어에 출시하고 수익 구조를 만들 때,

## 1. 한 줄 요약

**여러 매장을 가진 외식 브랜드의 본사와 매장이 같이 쓰는 운영 앱.**
매장은 마감·입고·지출·스케줄·출퇴근을 기록하고, 본사는 그 데이터로 정산·급여·인사·광고·리뷰를 관리한다. 매일 아침 자동으로 리뷰를 모으고 광고 성과를 분석하며, 필요한 사람에게 푸시로 알려준다.

- 운영 주체: 베스트메이트컴퍼니(주)
- 사용 중인 브랜드·매장: 제이드앤워터 4개 매장(옥수·스타필드하남·성수LCDC·서울역) + 정다미 서울역점
- 사용자: 대표, 본사 팀(마케팅·운영·디자인·R&D·HR), 각 매장 지점장, 매장 직원
- 형태: 폰 브라우저에서 쓰는 웹앱(홈 화면에 추가하면 앱처럼 동작하는 PWA). 아직 스토어 출시 전.

## 2. 누가 어떤 화면을 쓰나

| 계정 종류 | 누구 | 보는 범위 |
|---|---|---|
| 마스터(대표) | 짱대표님 | 전 매장·전 기능. 가입 승인, 금전대차, 광고 리포트(현재 시범 운영) 포함 |
| 본사 팀 계정 | 마케팅·운영·디자인·R&D·HR | 전 매장 게시판·주간보고·월간계획·입금요청·리뷰리포트. 팀별로 추가 권한(HR→인사, R&D→재고, 마케팅→광고·마감 열람) |
| 지점장(매장 계정) | 매장당 1명 | 자기 매장 운영 전부 + 월말정산·급여신고·매출 목표 설정·체험단 관리 |
| 직원 계정 | 매장 직원 | 자기 매장 기록 입력·출퇴근·스케줄·공지·내 평가. 급여·정산·채팅방 일부는 제외 |

가입은 앱에서 직접 하고 대표가 승인해야 쓸 수 있다. 계정은 "브랜드 → 매장 → 계정" 구조로 묶여 있어 다른 브랜드 데이터는 서로 보이지 않는다.

## 3. 기능 목록

### 매장 일상 운영
- **마감입력**: 하루 매출(현금·카드·배달앱별), 할인, 비고. 토스포스 연결 매장은 결제 내역이 자동으로 들어온다.
- **입고 입력**: 거래처별 입고 금액·영수증 사진.
- **현장지출**: 매장에서 쓴 비용 기록·영수증.
- **입금요청**: 매장이 본사에 보내는 지급 요청(급여·거래처 대금 등), 본사가 처리 상태 관리.
- **재고관리**: 품목 등록, 재고 실사, 생산 수량(R&D 팀도 열람).
- **스케줄러**: 날짜별 근무 배치, 근무 프리셋, 휴게시간.
- **GPS 출퇴근**: 매장 반경 50m 안에서만 출근·퇴근 기록, 스케줄과 비교해 지각·조퇴·결근 자동 표시. 출근 30분·10분 전, 퇴근 30분·10분 전 푸시 알림.
- **매출 분석 / 월간 분석 / 요일 분석 / 실시간 코스트**: 마감 데이터로 매출 추이, 원가율, 요일별 패턴.
- **매출 목표**: 지점장이 월 목표를 정하면 홈에 달성률·월말 예상이 표시(대표 홈에는 매장 타일마다 진행 바).

### 본사·경영
- **월말정산**: 매장별 월 손익(매출, 배달 플랫폼 수수료, 본사 운영비 적립 등).
- **급여신고**: 매장 급여 내역을 정리해 노무법인·세무사에게 메일로 전송.
- **HR / 인사**: 직원 명단, 입·퇴사, 보건증, 점장 평가·직원 자기평가(평가 루브릭 포함).
- **금전대차**: 매장 투자·상환 이력(지분 상환 구조 관리).
- **게시판**: 공지·업무 요청·체크리스트, 팔로워·댓글·첨부, 완료 처리, 미처리 알림.
- **주간보고**: 매장 주간 보고서 작성·열람, 일요일 리마인더, 구글 드라이브에 자동 보관.
- **월간계획**: 본사 일정 달력(/plan), 홈에는 "이번 주 일정" 띠.
- **채팅**: 1:1 메시지, 매장별·본사 채팅방, 파일 전송.
- **가입승인 / 매장 접근 제어**: 대표가 계정을 승인하고 매장·팀을 연결.

### 마케팅 자동화
- **리뷰리포트**: 매일 아침 구글 평점·리뷰 수, 네이버 블로그 후기를 모으고 AI가 요약. 매장별 추이.
- **광고 리포트**(현재 대표 계정만 시범): 네이버 검색광고 성과를 매일 가져와 주간 리포트, 시간대·요일별 효율, 캠페인 ON/OFF·예산 조정, 손익분기, 날씨·특이일 반영, 검색 노출 순위.
- **리뷰노트 체험단**: 모집글 작성(AI 초안) → 지원자 블로그 점수(A/B/C) → 지점장 승인 → 리뷰노트에 선정 반영 → 선정자 셀프 방문 예약 링크 → 방문·리뷰 등록 추적. 맥미니에서 돌아가는 작업기가 리뷰노트와 연결.
- **홈 실시간 매출**: 토스포스 결제 데이터로 오늘 매출을 매장별로 실시간 표시.

### 알림
- 웹 푸시(브라우저 알림): 출퇴근, 게시판 미처리, 주간보고, 월간계획, 체험단 방문, 입금요청 등.
- 메일: 급여신고(노무법인·세무사).

## 6. 기술 구조 (요약)

- **앱**: Next.js 16(App Router) + React, 서버 액션 중심. 차트는 Recharts.
- **DB**: Supabase(PostgreSQL). 테이블 약 60개, 마이그레이션 파일 115개(모두 저장소 `supabase/`에 보관, 재실행 가능). 행 단위 보안(RLS)으로 브랜드·매장별 데이터 격리.
- **환경**: 그린(테스트, 무료 플랜)·블루(운영)로 분리. 모든 변경은 그린에서 확인 후 블루로.
- **모바일**: PWA — 홈 화면 추가, 서비스 워커로 푸시 수신. 네이티브 앱 코드는 아직 없음.
- **자동화 보조 장비**: 맥미니 1대(리뷰노트 로그인 세션 유지, 지도 순위 수집, 매일 점검 루틴).
- **규모**: 화면 45개, API 17개(크론 10개, 연동 7개).

## 7. 스토어 출시를 위해 필요한 것

지금은 "로그인한 직원만 쓰는 내부 업무 앱"이다. 이 형태 그대로 공개 스토어에 올리면 심사에서 막힐 가능성이 크므로, 출시 방식부터 정해야 한다.

### 출시 방식 3가지
1. **지금처럼 PWA 유지**(스토어 없음): 비용 0, 아이폰은 "홈 화면에 추가"해야 푸시가 됨. 외부 고객에게 팔기엔 설치 안내가 번거롭다.
2. **웹앱을 그대로 감싸서 앱으로**(Capacitor 또는 안드로이드 TWA): 기존 화면 그대로 쓰고 푸시·위치 권한을 앱 방식으로 바꾼다. 개발 2~4주 수준. 애플은 "웹사이트를 그대로 감싼 앱"을 거절하는 규정(4.2 최소 기능)이 있어 네이티브 요소(앱 푸시, 위치, 카메라 영수증 촬영 등)를 넣어 설명해야 한다.
3. **비공개 배포**: 우리 직원용이라면 Apple Business Manager(커스텀 앱)·구글 플레이 관리형(사내 전용)으로 심사 부담 없이 배치할 수 있다. 외부 판매용 공개 앱과는 별도.

→ 외부 클라이언트에게 팔 계획이면 2번(공개 앱) + 3번(초기 내부용)을 같이 가는 게 현실적이다.

### 심사 통과용 체크리스트
- [x] 개인정보처리방침·이용약관 웹페이지 — `/privacy`, `/terms` (로그인 없이 열림, 2026-11-01 그린). 운영사 주소·사업자등록번호·보호책임자 연락처는 대표님 확인 후 채울 것
- [x] 앱 안에서 계정 삭제 기능(애플·구글 모두 요구) — 프로필 화면 '계정 삭제'(비밀번호 재확인 → 프로필 익명화 + 로그인 계정 영구 차단, 업무 기록은 '탈퇴한 사용자'로 보존, 마스터 계정은 불가). 2026-11-01 그린, DB: `supabase/migration_account_deletion.sql`
- [ ] 위치 권한 사용 이유 문구(출퇴근 GPS), 알림 권한 문구
- [ ] 심사용 테스트 계정(로그인 전용 앱은 반드시 제공) + 데모 매장 데이터
- [ ] 앱 아이콘·스크린샷·설명문(현재 아이콘 192/512 있음, 스토어 규격 아트워크 필요)
- [ ] 결제가 들어가면: 애플은 앱 내 구독을 인앱 결제로 해야 함(수수료 15~30%). B2B 구독은 웹에서 결제하고 앱은 로그인만 하는 방식이 일반적(그래야 수수료 회피 가능)
- [ ] 사업자 명의 개발자 계정(애플 연 99달러, 구글 1회 25달러), D-U-N-S 번호

### 제품으로 팔기 위해 앱 안에서 바꿔야 할 것
- **셀프 온보딩**: 지금은 대표가 매장·계정을 SQL이나 승인 화면으로 연결한다. 브랜드 생성 → 매장 추가 → 초대 링크로 직원 가입까지 고객이 혼자 하게 해야 한다.
- **연동 키 입력 화면**: 토스포스·네이버 광고·구글 키를 고객이 직접 넣고 검증하는 화면(네이버는 일부 있음). 키는 암호화 보관.
- **브랜드별 커스터마이징**: 로고·용어(예: "마감", "입고")·급여신고 수신처·평가 항목.
- **과금·플랜 관리**: 매장 수·기능 모듈별 요금, 결제 수단, 미납 시 제한.
- **데이터 격리 재점검**: 지금도 브랜드별 RLS가 있지만, 외부 고객이 들어오면 보안 점검(침투 테스트 수준)을 한 번 받는 게 좋다.
- **자동화 장비 의존 제거**: 리뷰노트·지도 순위는 맥미니 1대에 묶여 있다. 고객이 늘면 서버화하거나 "리뷰노트 공식 제휴"가 필요.
- **고객 지원·장애 대응**: 헬스체크가 이미 있으니, 고객별 상태 페이지와 문의 채널만 붙이면 된다.

## 8. 수익 구조 후보

| 모델 | 내용 | 참고 |
|---|---|---|
| **매장당 월 구독(SaaS)** | 기본(마감·입고·지출·스케줄·출퇴근·게시판) + 모듈(정산·급여, 리뷰·광고 자동화, 체험단) | 비슷한 외식 운영 SaaS가 매장당 월 3만~10만 원대. 모듈 추가 시 가산 |
| **운영대행(MSO) 수수료** | 앱 + 사람(마케팅·리뷰 답글·체험단 운영)을 묶어 매장 매출의 일정 비율 또는 월 정액 | 기존 메모([운영 MSO 사업 계획])의 본래 목표. 앱은 대행 원가를 낮추는 도구 |
| **셋업·컨설팅비** | 첫 연동(토스·네이버·구글), 평가 체계·정산 구조 설계 | 1회성, 초기 현금흐름 |
| **광고 집행 수수료** | 네이버 광고 예산을 앱이 자동 조정해 주고 집행액의 일정 비율 | 광고 리포트 모듈이 이미 캠페인 ON/OFF·예산 제어를 한다 |
| **데이터 리포트** | 상권·요일·시간대 분석을 브랜드 단위로 판매 | 매장 수가 쌓여야 가치가 생김 |

### 구현된 요금 뼈대 (2026-11-01)
- **기본 기능**(무료 — 앱은 무료로 열어 모든 자영업자가 쓰게 한다, 2026-11-01 대표님 방향): 마감입력·입고·현장지출·입금요청·재고·스케줄러·매출 분석·매출 목표·게시판·메시지·주간보고·월간계획·포스(토스) 연동
- **추가 모듈**(브랜드가 월 결제로 추가, 매장당 요금 초안): 정산·급여 2만 / 인사·평가(GPS 출퇴근 포함) 1만 / 리뷰·광고 자동화 3만 / 체험단 운영 2만. 포스 연동은 단발성 작업이라 기본에 포함(2026-11-01 결정)
- 동작: 매장 계정(지점장·직원)은 브랜드가 켠 모듈의 메뉴만 보이고, 주소로 들어가면 `/upgrade` 안내 화면. 본사 계정은 항상 전부. 대표는 `/modules`(빠른 메뉴 '기능 구독')에서 브랜드별로 켜기/끄기/체험 30일. 모듈 정의는 `lib/modules.ts`, 상태는 DB `brand_modules`(`supabase/migration_brand_modules.sql`).
- 남은 것: 카드 정기결제(토스페이먼츠 빌링 — 사업자 PG 계약 필요) → 브랜드 대표가 직접 켜고 결제, 미납 시 자동 끔.

추천 순서: 내부 4~5개 매장으로 실증(지금) → 지인 브랜드 1~2곳에 무료/할인 베타(온보딩·격리 검증) → 매장당 구독 + MSO 패키지로 정식 판매.
